# Инструкция по установке и запуску Dev Container

## 1. Назначение

Dev Container — подготовленное окружение разработки, в котором установлены необходимые инструменты и зависимости проекта.

Использование Dev Container позволяет всем разработчикам работать в одинаковом окружении, независимо от операционной системы и локальных настроек компьютера.

В контейнере автоматически устанавливаются и настраиваются:
- Go и golangci-lint;
- Air для автоматического перезапуска Go-приложения;
- Java 21 и Maven;
- Node.js и npm;
- Python 3.12;
- Bruno CLI;
- PostgreSQL Client;
- Docker CLI.

Также автоматически загружаются зависимости Go Backend, Frontend и Java Backend.

## 2. Предварительные требования

Перед началом работы необходимо установить следующие программы.

### 2.1. Docker Desktop

Скачать и установить Docker Desktop:

https://www.docker.com/products/docker-desktop/

После установки запустить Docker Desktop и убедиться, что Docker работает.

Проверить установку можно командами:

```bash
docker --version
docker compose version
```

Для Linux можно использовать Docker Engine с Docker Compose Plugin вместо Docker Desktop.

### 2.2. Visual Studio Code

Скачать и установить Visual Studio Code:

https://code.visualstudio.com/

### 2.3. Расширение Dev Containers

В Visual Studio Code открыть раздел Extensions (`Ctrl + Shift + X`).

Найти и установить расширение:

**Dev Containers** от Microsoft.

Ссылка:

https://marketplace.visualstudio.com/items?itemName=ms-vscode-remote.remote-containers

## 3. Получение проекта

Клонировать репозиторий проекта:

```bash
git clone <URL_РЕПОЗИТОРИЯ>
```

Перейти в каталог проекта:

```bash
cd project__K
```

Открыть проект в Visual Studio Code:

```bash
code .
```

Если проект уже открыт в VS Code, достаточно перейти к следующему шагу.

## 4. Запуск Dev Container

После открытия проекта Visual Studio Code может предложить открыть его в контейнере.

Необходимо выбрать:

**Reopen in Container**

Если предложение не появилось, выполнить следующие действия:

1. Открыть палитру команд сочетанием `Ctrl + Shift + P`.
2. Найти команду `Dev Containers: Reopen in Container`.
3. Выбрать её и дождаться создания контейнера.

При первом запуске Docker автоматически:
- загрузит базовый образ Debian Trixie;
- создаст контейнер разработки;
- установит необходимые инструменты;
- создаст и подключит необходимые Docker Volumes;
- запустит PostgreSQL;
- выполнит скрипт `.devcontainer/post-create.sh`;
- установит зависимости всех частей проекта.

**Важно:** первый запуск может занять некоторое время, поскольку необходимо загрузить образы и зависимости проекта.

Не следует закрывать VS Code до завершения настройки.

## 5. Автоматическая установка зависимостей

После создания контейнера автоматически запускается скрипт:

```text
.devcontainer/post-create.sh
```

Он выполняет следующие действия:

1. Подготавливает shell-скрипты проекта.
2. Проверяет наличие PostgreSQL Client и при необходимости устанавливает его.
3. Настраивает PATH для Go.
4. Устанавливает Air, если он отсутствует.
5. Устанавливает Bruno CLI, если он отсутствует.
6. Запускает установку зависимостей проекта.
7. Проверяет доступность установленных инструментов и выводит их версии.

Для установки зависимостей проекта используется:

```text
Scripts/install-dependencies.sh
```
## 6. Запуск и проверка проекта

Для одновременного запуска всех компонентов проекта (Frontend, Java Backend и Go Backend) предусмотрен единый скрипт:

```bash
./Scripts/app-start.sh
```

Скрипт запускает:
- **Frontend** — клиентскую часть приложения;
- **Java Backend** — серверную часть на Java;
- **Go Backend** — серверную часть на Go.

Для проверки работоспособности проекта необходимо:

1. Открыть терминал VS Code внутри Dev Container.
2. Перейти в корневую директорию проекта.
3. Выполнить команду:

```bash
./Scripts/app-start.sh
```

4. Дождаться запуска всех трёх компонентов.
5. Проверить сообщения в терминале и убедиться, что сервисы запустились без ошибок.

**Важно:** скрипт необходимо запускать из корневой директории проекта. Не закрывайте терминал во время работы приложения.

Для остановки запущенных компонентов используйте `Ctrl + C`.


## 7. PostgreSQL

PostgreSQL запускается отдельным Docker-контейнером через Docker Compose.

Параметры подключения внутри Dev Container:

| Параметр | Значение |
|---|---|
| Host | `postgres` |
| Port | `5432` |
| Database | `postgres` |
| Username | `postgres` |
| Password | `postgres` |

Строка подключения для Java Backend:

```text
jdbc:postgresql://postgres:5432/postgres
```

Для подключения к PostgreSQL из терминала контейнера:

```bash
psql -h postgres -U postgres -d postgres
```

При необходимости подключения к базе данных с компьютера-хоста используется порт `5433`:

```text
localhost:5433
```

## 8. Повторное открытие и пересборка контейнера

При последующих открытиях проекта можно использовать обычный запуск VS Code.

Контейнер и Docker Volumes сохраняются, поэтому повторно загружать все зависимости обычно не требуется.

Если необходимо пересоздать окружение:

1. Открыть палитру команд `Ctrl + Shift + P`.
2. Выбрать `Dev Containers: Rebuild Container`.

Если требуется полностью пересоздать контейнер с очисткой его кэшей и зависимостей, можно использовать:

`Dev Containers: Rebuild Container Without Cache`.

**Внимание:** не удаляйте Docker Volumes без необходимости. В них могут храниться зависимости и данные PostgreSQL.
