Версия 0.5 от 17 ноября 2026 года. Две матрицы распределяют ответственность за документацию и разработку итоговой версии учебного проекта к защите. Домнин отвечает за QA, Ручкина — за интеграционные данные, ADR и трассируемость, Проценко — за аналитику.

Обозначения

R — выполняет работу. A — отвечает за итог и принимает результат. C — консультирует и участвует в согласовании. I — получает информацию о результате. A/R — совмещает выполнение и ответственность за итог.

В каждой строке один A и не менее одного R. R1–R5 — коды участников; они не обозначают уровни ответственности RACI. Внутренняя приёмка команды не заменяет проверку преподавателем.

Разделение ролей в разработке

Бульдин отвечает за Java backend и архитектуру, Домнин — за Go-подсистему и алгоритм планирования, Проценко — за React-интерфейс. Ручкина как Fullstack-разработчик отвечает за интеграцию React с backend, участвует в формах и подключении API, согласует контракты данных между компонентами.

Схемы и миграции Java ведёт Бульдин, Go — Домнин. Ручкина согласует интеграционные наборы и правила валидации; изменения схем выполняют владельцы сервисов. Объекты данных 1С ведёт Корепанова. Проценко ведёт аналитику и требования. Домнин координирует QA; каждый разработчик тестирует и исправляет свой компонент.

Совместная подготовка документов

Проценко готовит аналитическое содержание карточки, MoSCoW, Vision и требований. Домнин проверяет критерии приёмки, собирает и оформляет документы. Ручкина ведёт ADR, расширенную трассируемость и описание интеграционных данных; Бульдин отвечает за архитектуру и согласованность решений. В README каждый участник описывает свою часть, Бульдин объединяет инструкции.

Описание затрат и себестоимости относится к функциям Should. Наличие строки в RACI не меняет их приоритет в MoSCoW.

Владение схемами данных: Java — Бульдин; Go — Домнин; 1С — Корепанова. Каждый отвечает за схемы и миграции своего компонента. В общих строках Бульдин координирует итог; Ручкина согласует интеграционные поля.

Домнин отвечает за методику и сводный результат QA; Проценко выполняет контрольный замер З-19, Бульдин ведёт сквозную приёмку З-27. Разработчики проверяют свои компоненты. Строки RACI распределяют ответственность и не подтверждают готовность функционала или проведение проверок.
