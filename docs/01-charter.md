Продукция предприятия:

Предприятие изготавливает металлические детали для промышленного оборудования — валы, втулки, шестерни и кронштейны. Детали производятся партиями по заказам клиентов. Для каждого вида продукции задан технологический маршрут: последовательность операций, необходимое оборудование и нормы времени изготовления.

Дата утверждения кейса: 22 сентября 2026 годаРепозиторий проекта: GitVerse

Назначение проекта

Учебная система формирует производственный план по заказам с учётом последовательности технологических операций, рабочего календаря и доступных мощностей рабочих центров. Пользователи получают мастер-план, сведения о загрузке ресурсов и прогноз соблюдения сроков.

Цель проекта

Повысить предсказуемость выполнения производственных заказов и эффективность использования оборудования за счёт автоматизированного формирования мастер-плана с учётом сроков, приоритетов заказов и доступных мощностей рабочих центров, чтобы сократить просрочки и предотвратить перегрузку ресурсов.

Архитектура и ответственность

React обращается к Java, Java — к Go. Java хранит изделия, технологии и заказы с позициями; Go хранит рабочие центры, календарь, планы и назначения. Каждая подсистема владеет своей БД. За схемы Java отвечает Бульдин, Go — Домнин, 1С — Корепанова; Ручкина согласует интеграционные данные и подключение React.

Базовый обмен с 1С — согласованный файл, формируемый Java из плана Go. JSON предложен в ADR; окончательный формат подлежит согласованию. Стоимость и материалы — Should. Текущие локальные порты по описанию Java: Java 8080, Go 8081.

Следующий этап: учёт выполнения и перепланирование

R33–R39 относятся к будущему этапу после MVP. Работник вручную отмечает выполнение заданий закреплённого станка и сообщает о проблемах. Начальник цеха видит план/факт в пределах своих полномочий, уточняет задержки и простои, запускает пересчёт и подтверждает актуальный вариант. Это не автоматический сбор телеметрии и не полноценная MES.

React передаёт факты в Java; Java хранит автора, время и устойчивый идентификатор производственной операции, затем отправляет согласованный снимок в Go. Go переносит только оставшуюся работу. Завершённое не планируется повторно; частичное выполнение переносится только при технологической допустимости. Подтверждение устаревшего варианта отклоняется; замена резервов атомарна. 1С не является обязательным посредником пересчёта.
