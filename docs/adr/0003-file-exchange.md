ADR 0003 Файловый обмен планом с 1С

Кейс 22 · Мастер-план · Редакция 0.3 · 16 ноября 2026 года

Подготовила: Ручкина Алёна Игоревна. Архитектурное ревью: Бульдин Захар Андреевич.

Статус редакции: на согласовании. В исходной версии решение отмечено как принято; новые уточнения не считаются согласованными без ревью команды.

Связи: R11, R12, R30; дополнительно R19, R20; A02, A03, A06. Сценарии: UC06, UC07; UC08 только Should.

Сохраняется базовое решение об обмене через файл. Java формирует файл из данных плана Go, 1С импортирует его и строит отчёт. Документы о текущей Java-реализации не подтверждают переход на HTTP-интеграцию с 1С.

Контекст и решение

Для Must требуются один согласованный формат, отсутствие дублей при повторном импорте и согласованность отчёта с планом. Материалы, цены и себестоимость — отдельный Should; складские остатки, закупки и блокировка планирования по дефициту не включаются в базовый обмен.

Экспорт имеет одного владельца — Java. Go предоставляет исходный план и данные загрузки через внутренний API. 1С отвечает за проверку схемы, ссылок, идентичности набора и сохранение импортированных данных. Утверждение исходного ADR «Java/Go формируют файл» заменено однозначным распределением.

Предлагаемый контракт файла

Для согласования предлагается JSON: он сохраняет структуру план → позиции → операции без дополнительных связанных CSV-файлов. Это предложение редакции 0.3, а не уже утверждённый формат. Второй формат для MVP не требуется.

| Группа | Состав предлагаемой схемы |
| --- | --- |
| Метаданные | schemaVersion, planId, planRevision, exportedAt. planRevision — новый реквизит обмена, которого нет в текущем Go DTO. |
| Заказ и план | orderId, dueDate, status, plannedStartAt, plannedFinishAt, onTime; снимок названий изделий для отчёта. |
| Позиции и операции | orderItemId, productId, quantity; scheduledOperationId, operationId, sequenceNumber, operationType, workCenterId, workCenterCode, workCenterTitle, startAt, finishAt. |
| Загрузка | Период отчёта, часовой пояс, доступные и занятые интервалы или согласованные агрегаты. Одного списка операций недостаточно для расчёта процента загрузки. |

Версию схемы файла и ревизию содержимого плана следует различать. Наличие перечисленных реквизитов в файле требует реализации экспортёра; текущий Java DTO не гарантирует все эти поля.

Повторный импорт и согласованность

Предлагаемый ключ импорта — (planId, planRevision). Повтор файла с тем же ключом и тем же содержимым не создаёт новых записей. То же значение ключа с другим содержимым отклоняется как конфликт. Сравнение выполняется по согласованному нормализованному содержимому, а не по времени exportedAt.

Новая ревизия импортируется атомарно; для отчёта активируется только полностью проверенная версия. Если повторный расчёт создаёт новый planId, контракт должен явно определить, какой предыдущий план он заменяет. Правило выбора действующего плана заказа пока не определено в Go API и должно быть согласовано до реализации.

При ошибке схемы, обязательных полей, ссылок или времени импорт отклоняется целиком с понятным сообщением. Старый успешно импортированный набор остаётся доступным. Изменения статуса также требуют новой согласованной ревизии или другой утверждённой политики обновления.

Альтернативы и последствия

HTTP-интеграция позволила бы автоматизировать обмен, но требует отдельного согласования API и доступности 1С. CSV проще для плоских данных, но сложнее для вложенного плана. Файловый обмен воспроизводим и удобен для демонстрации, однако включает ручную передачу и требует повторного импорта после изменения плана.

Решение не устраняет зависимость от платформы 1С: импортёр необходимо проверить на выбранной версии и конфигурации. Формат, ревизии и полнота данных загрузки остаются открытыми решениями. Проверки: T-11, T-12, T-20. Источники: S1, S2, S5, S7, S8.
