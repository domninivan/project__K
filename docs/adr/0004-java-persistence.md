ADR 0004 Java Spring Boot и явная конфигурация

Кейс 22 · Мастер-план · Редакция 0.3 · 16 ноября 2026 года

Подготовила: Ручкина Алёна Игоревна. Архитектурное ревью: Бульдин Захар Андреевич.

Статус редакции: на согласовании. В исходной версии решение отмечено как принято; новые уточнения не считаются согласованными без ревью команды.

Связи: R13, R31, R32; A02, A04, A07, A08. Сценарии: UC01, UC02.

Описание «Spring без Boot, WAR и внешний Tomcat» заменено текущим стеком: Java 21, Spring Boot 3.5.x, встроенный Tomcat, XML-конфигурация и native Hibernate SessionFactory. Основание — документ о реализованной Java-части, S3.

Контекст и решение

Spring Boot запускает веб-приложение, а явная конфигурация инфраструктуры сохраняется. applicationContext.xml подключается через @ImportResource. Прикладные компоненты регистрируются аннотациями Spring; наличие Boot не означает переход на Spring Data JPA.

| Область | Зафиксированное состояние |
| --- | --- |
| Runtime и web | Java 21, Spring Boot 3.5.x, embedded Tomcat; Java слушает 8080. |
| Persistence | Hibernate 5.6 Jakarta, native SessionFactory, HQL, DAO + Service, PostgreSQL. |
| Конфигурация | Смешанная: XML для инфраструктуры и аннотации для прикладных компонентов. |
| Клиент Go | RestClient, бин goRestClient через factory-method=create, базовый URL из go.base-url. |
| Транзакции | Бизнес-операции выполняются в сервисном слое. Управляемую сущность при cancelOrder не требуется дополнительно merge. |
| DTO | Controller работает с HTTP; mapper преобразует модели в DTO; сервис не зависит от response DTO. |

В исходном ADR ссылка на обязательный запрет Boot в рамках курса не подтверждена предоставленными требованиями и удалена. Конкретный пул соединений, режим hbm2ddl и способ упаковки не объявляются установленными без проверки актуального проекта.

Обоснование и контроль

Альтернативы

Чистый Spring с WAR и внешним Tomcat был описан ранее, но перестал соответствовать реализации. Полный переход на Spring Data JPA изменил бы DAO и способ работы с Hibernate. Текущий вариант сохраняет существующие SessionFactory, HQL и сервисные транзакции, одновременно используя запуск Boot.

Последствия

Преимущество — документация соответствует реальному способу запуска, а инфраструктура остаётся явной. Риск — сочетание Boot и ручного XML может создать дубли DataSource, SessionFactory или менеджеров транзакций. Конфигурацию нужно проверять запуском приложения и интеграционными сценариями, а не только компиляцией.

Пакет Hibernate должен соответствовать Jakarta API, используемому приложением. Управление версиями зависимостей фиксируется в Maven; в этой редакции не утверждается официальная совместимость произвольных комбинаций версий и не предлагается незапрошенный переход на другой ORM.

Проверка реализации

Зафиксировать commit и команду сборки; запустить Java на 8080, Go на 8081; проверить создание и чтение заказа с позициями, отмену без удаления, чтение изделия и его технологии. DAO заказа использует join fetch для items и product, чтобы mapper мог сформировать ответ без LazyInitializationException.

При остановленном Go проверить 503, при отсутствии плана — 404, при другой ошибке Go — предусмотренный 502. В источнике сообщается об успешном Maven compile; эта редакция документа не является протоколом повторного запуска тестов.
