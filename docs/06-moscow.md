# Приоритеты MoSCoW

Источник: `MoSCoW.docx`. Перенос в Markdown: 21.11.2026. Статусы и оценки сохранены из источника; перенос не означает утверждения решений или выполнения проверок.

Приоритеты требований MoSCoW

Кейс №22 • План производства по заказам (мастер-план)

Редакция 0.3 от 17 ноября 2026 года. Приоритеты определяют состав текущей версии проекта к защите: Must — обязательные функции; Should — желательные; Could — дополнительные при наличии времени; Won’t — вне текущей сдачи. Таблицы описывают требования, а не подтверждённую готовность кода. Будущий этап R33–R39 не расширяет Must автоматически.

Must — обязательно

| Функция | Содержание |
| --- | --- |
| Справочник деталей и технологий | Просмотр деталей, последовательности технологических операций и нормативного времени изготовления. |
| Создание и просмотр производственных заказов | Клиент задаёт одну или несколько позиций (изделие и количество), общую желаемую дату, комментарий и контакты; сотрудник назначает внутренний приоритет. Список и карточка заказа. Контакты клиента предусмотрены R02, но пока отсутствуют в DTO dueDate, comment, items; модель и API требуют расширения. Приоритет не вводится клиентом. |
| Производственные ресурсы | Хранение рабочих центров, поддерживаемых типов операций и доступной мощности. |
| Производственный календарь | Учёт рабочих и нерабочих дней, доступного времени работы ресурсов. |
| Формирование мастер-плана | Расчёт длительности операций по нормативам и количеству деталей; распределение по рабочим центрам с учётом приоритетов, последовательности операций и доступной мощности. |
| Контроль сроков заказов | Определение плановой даты завершения, признака выполнения в срок и величины планового опоздания. |
| Просмотр мастер-плана | Таблица запланированных операций с указанием заказа, рабочего центра, времени начала и окончания. |
| Диаграмма Ганта | Визуальное представление операций во времени с привязкой к заказам или рабочим центрам. |
| Отображение загрузки | Просмотр занятой и доступной мощности рабочих центров по дням. |
| Основные KPI | Доля заказов, запланированных в срок; процент загрузки рабочих центров; количество заказов с плановым опозданием. Показатели рассчитываются по плану и не отражают фактическое выполнение. |
| Обмен данными с 1С | Выгрузка результатов планирования из Java в одном согласованном формате и загрузка файла в 1С. Проверка структуры и связей, защита от повторного импорта, атомарное сохранение набора. |
| Отчётность в 1С | Формирование отчёта по производственному плану и загрузке рабочих центров на основе принятого набора данных. Расчёт материалов и себестоимости не является условием получения этого отчёта. |
| Валидация и обработка ошибок | Проверка обязательных полей, допустимых значений и связей; понятные сообщения пользователю; сохранение целостности данных при ошибках. |
| Обязательные условия качества R27–R32 | Условия качества сохраняются в составе Must наряду с R01–R13. Численные критерии и корректность подтверждаются испытаниями по программе проверок; описание требования не заменяет результат проверки. |

Should — желательно

| Функция | Содержание |
| --- | --- |
| Перепланирование | Пересчёт плана при изменении заказа, календаря или доступности рабочего центра. Пересчёт по фактам выполнения работников относится к следующему этапу R33–R39. |
| Управление статусами заказов | Контроль допустимых переходов между статусами; отмена заказа с освобождением зарезервированной мощности. Java DELETE /api/orders/{id} переводит заказ в CANCELLED без удаления. Освобождение мощности Go и согласование статусов заказа и плана остаются отдельной незавершённой частью R15. |
| Поиск и фильтрация | Отбор заказов и операций по срокам, приоритетам, статусам и рабочим центрам. |
| Авторизация и разграничение доступа | Вход в систему и разделение возможностей планировщика, руководителя и администратора. |
| Учёт недоступности оборудования | Регистрация периодов ремонта или простоя рабочего центра и их учёт при планировании. |
| Расчёт затрат на материалы в 1С | Хранение норм расхода и цен материалов; расчёт стоимости материалов на одну деталь и на весь заказ с учётом количества деталей. |
| Расчёт плановой себестоимости изготовления в 1С | Расчёт себестоимости одной детали и всего заказа: затраты на материалы и выполнение технологических операций по установленным ставкам. |

Could — при наличии времени

| Функция | Содержание |
| --- | --- |
| Тепловая карта загрузки | Цветовое представление загрузки рабочих центров по периодам. |
| История версий плана | Хранение и просмотр предыдущих результатов планирования. Пользовательская история версий не заменяет техническую проверку актуальности снимка при подтверждении плана. |
| Сравнение планов | Отображение изменений сроков, назначения рабочих центров и загрузки после перепланирования. |
| Расширенная аналитика | Средняя величина планового опоздания, свободная мощность, количество операций, затронутых перепланированием. |
| Редактирование справочников через интерфейс | Добавление и изменение деталей, технологий, рабочих центров и календаря уполномоченным пользователем. |
| Дополнительные форматы экспорта | Выгрузка отчётов в дополнительные форматы помимо основного формата обмена с 1С. |

Won’t — вне текущей сдачи

| Функция | Содержание |
| --- | --- |
| Машинное обучение | Прогнозирование длительности операций или других показателей с помощью ML. |
| Промышленный оптимизатор | Поиск математически оптимального расписания по множеству критериев. |
| Складской учёт и закупки | Управление остатками материалов, поставками и закупками. Расчёт плановых затрат на материалы в 1С в это ограничение не входит. |
| Управление оборудованием | Подключение к станкам, сбор телеметрии и отправка управляющих команд. |
| Отдельное мобильное приложение | Разработка приложения для Android или iOS. |
| Промышленное внедрение | Развёртывание на реальном предприятии с промышленными требованиями к отказоустойчивости и сопровождению. |
| R33 — задания работника | После MVP: Работник видит операции закреплённого станка и их плановые параметры. |
| R34 — отметки выполнения | После MVP: работник фиксирует начало, завершение и выполненное количество. React передаёт факты в Java, где сохраняются автор и время. |
| R35 — план/факт и отклонения | После MVP: Работник сообщает о задержке или поломке; начальник видит план/факт и уточняет отклонение. Ввод ручной, без автоматического сбора телеметрии. |
| R36 — передача данных для пересчёта | После MVP: Java передаёт Go согласованный снимок фактов, остатков и недоступности для пересчёта. 1С не является обязательным посредником пересчёта. |
| R37 — пересчёт оставшейся работы | После MVP: Go пересчитывает оставшуюся работу, сохраняя завершённые операции и ограничения выполняющихся. Частично выполненная работа переносится только при технологической допустимости. |
| R38 — подтверждение нового плана | После MVP: начальник проверяет изменения и подтверждает актуальный вариант. Устаревший вариант отклоняется; резервы заменяются атомарно, без дублей. |
| R39 — устойчивость фактов и повторов | После MVP: Факты сохраняют устойчивую связь с операциями при смене плана; повтор команды не дублирует результат. Используется устойчивый идентификатор производственной операции. |

Для R33–R39 перед включением в следующую итерацию согласуются оценки, сроки, ответственные, права и критерии приёмки. Это развитие проекта после текущей сдачи, а не полноценная MES. Требования текущего этапа: Must — R01–R13 и R27–R32; Should — R14–R20; Could — R21–R26.
