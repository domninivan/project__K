Следующий этап: учёт выполнения и перепланирование

R33–R39 относятся к будущему этапу после MVP. Работник вручную отмечает выполнение заданий закреплённого станка и сообщает о проблемах. Начальник цеха видит план/факт в пределах своих полномочий, уточняет задержки и простои, запускает пересчёт и подтверждает актуальный вариант. Это не автоматический сбор телеметрии и не полноценная MES.

React передаёт факты в Java; Java хранит автора, время и устойчивый идентификатор производственной операции, затем отправляет согласованный снимок в Go. Go переносит только оставшуюся работу. Завершённое не планируется повторно; частичное выполнение переносится только при технологической допустимости. Подтверждение устаревшего варианта отклоняется; замена резервов атомарна. 1С не является обязательным посредником пересчёта.

Требования и текущая реализация

Требования описывают целевой результат и не подтверждают готовность кода. Контакты клиента из R02 сохраняются в требованиях: текущий DTO dueDate, comment, items их не содержит, поэтому расширение модели и API остаётся открытой задачей. Производственный приоритет назначает сотрудник; значение по умолчанию Java не заменяет управление приоритетом.

DELETE /api/orders/{id} переводит заказ в CANCELLED без удаления. Освобождение мощности Go и согласование статусов заказа и плана — отдельная незавершённая часть R15. Контракты, сроки и проверки уточняются в ADR, плане работ и программе проверок; статус «выполнено» требует подтверждения.

Границы данных

Заказ, технология и факты будущего этапа принадлежат Java; ресурсы, календарь, планы и назначения — Go; импорт и отчётность — 1С. Прямое изменение чужих таблиц запрещено. Базовый обмен Java → 1С файловый. Подключение к станкам, зарплата и полноценная ERP/MES не добавляются.
