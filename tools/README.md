# Настройка шаблона и справочники

> Этот каталог предназначен прежде всего для организаторов. Скриптов и обязательной автоматизации здесь нет; студентам ничего запускать не требуется.

## Содержимое

| Файл | Назначение |
| --- | --- |
| [labels.json](labels.json) | Предлагаемые обозначения категорий задач. |
| [milestones.json](milestones.json) | Заготовка четырёх контрольных этапов без назначенных дат. |
| [TEMPLATE_VERSION](../TEMPLATE_VERSION) | Версия исходного каркаса, на основе которого создан проект. |

Оба JSON-файла используют локальный формат этого шаблона. Это не официальная схема импорта GitVerse и не готовые запросы к API. Добавление файлов в репозиторий не создаёт метки, вехи, команды или права доступа. Начинать работу можно без них.

Метки необязательны: если нужное значение уже представлено типом или другим полем задачи, не дублируйте его. Даты и критерии этапов согласуйте с куратором. Актуальный календарь ведите в одном месте — в паспорте либо в трекере со ссылками из паспорта.

## Публикация центрального шаблона

1. Создайте репозиторий в организации курса и разместите содержимое этой папки-шаблона в его корне: `README.md`, `TEAM.md`, `docs/` и остальные файлы должны находиться на первом уровне.
2. В GitVerse откройте «Настройки» → «Репозиторий», отметьте «Сделать репозиторий шаблоном» и нажмите «Обновить».
3. Согласуйте, кто создаёт проекты в организации и кому выдаются права. Создание из шаблона не заменяет настройку доступа.
4. До выдачи всем командам создайте один пробный проект на его основе. Проверьте состав файлов, доступ команды, основную ветку, создание задачи и запроса на слияние.

Для независимых командных проектов рекомендуемый сценарий — создание на основе шаблона. Если организационно выбран fork, объясните, что рабочие изменения нужно сливать в собственный проект команды, а не в центральную заготовку.

## Шаблоны задач и запросов

Образцы находятся в [docs/templates/](../docs/templates/). Это тексты для копирования, а не файлы автоматической настройки GitVerse. Каталоги `.gitea/ISSUE_TEMPLATE/` и `.gitea/PULL_REQUEST_TEMPLATE.md` описаны в документации Gitea, но автоматическую обработку этих путей GitVerse для данного комплекта не проверяли и не обещают.

Не заменяйте `.gitea` на `.gitverse` по аналогии без проверки поддержки. Если организатор настроит нативные шаблоны на платформе, обновите эту инструкцию и оставьте один источник текстов.

Метки создаются средствами трекера. Вехи доступны в GitVerse при включённом новом трекере «Задачи 2.0» и включённых задачах; для архивного репозитория создание и изменение вех недоступно. Если вехи не используются, достаточно таблицы этапов в паспорте.

## Что не включено

Нет скриптов `bootstrap` и `check_template`, CI/CD, Docker, зафиксированного стека и предметных CSV. Это намеренный состав базового документационного каркаса, а не незаполненные обязательные файлы.

Права, защиту основной ветки, обязательное ревью и выбранные проверки организатор настраивает отдельно. Для будущей автоматизации создавайте отдельный инструмент, который сначала показывает план, не хранит токен в репозитории и не меняет чужие проекты без подтверждения.

## Версия шаблона

Значение в `TEMPLATE_VERSION` обозначает версию каркаса, а не готовность продукта. Студентам не нужно менять его после каждого коммита. При согласованном переносе обновлений шаблона обновите версию и запишите перенос в запросе на слияние.

## Проверка перед выдачей студентам

Проверьте относительные ссылки, наличие всех файлов и чтение JSON. Отдельно проверьте на GitVerse создание пробного проекта и доступ участников. В этом комплекте нет автоматической проверки знаний или выполнения требований.
