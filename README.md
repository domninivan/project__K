## Начало работы с шаблоном

1. Заполните этот файл и [TEAM.md](TEAM.md). Уточните границы проекта в [паспорте](docs/01-charter.md) и согласуйте [требования](docs/02-requirements.md).
2. Прочитайте [правила совместной работы](CONTRIBUTING.md). Создайте первые задачи с ответственными и критериями готовности.
3. После выбора технологий заполните [архитектуру](docs/03-architecture.md) и [запись о выборе стека](docs/adr/0001-tech-stack.md). В шаблоне никакой стек не выбран.
4. Добавьте код, проверки и точные инструкции запуска. На контрольных точках обновляйте [журнал прогресса](docs/04-progress.md).

Служебные справочники в `tools/` необязательны. Для начала работы с шаблоном не требуется запускать скрипты или устанавливать какой-либо язык программирования.

## Структура

```text
.
├── README.md                  # Обзор и запуск проекта
├── TEAM.md                    # Участники и ответственность
├── CONTRIBUTING.md            # Работа с задачами и изменениями
├── docs/
│   ├── 01-charter.md           # Паспорт и границы проекта
│   ├── 02-requirements.md      # Требования и критерии приёмки
│   ├── 03-architecture.md      # Устройство и выбранные технологии
│   ├── 04-progress.md          # Результаты контрольных точек
│   ├── adr/                   # Короткие записи важных решений
│   ├── images/                # Схемы и скриншоты документации
│   └── templates/             # Тексты задач и запросов на слияние
├── src/README.md              # Исходники и их размещение
├── tests/README.md            # Проверки и их запуск
├── data/sample/README.md      # Безопасные демонстрационные данные
├── tools/                     # Инструкция и справочники для настройки
├── TEMPLATE_VERSION           # Версия исходной заготовки, не продукта
└── .gitignore
```

Расположение исходников можно адаптировать под выбранные технологии: например, добавить `frontend/`, `backend/`, `app/` или `notebooks/`. Обновите описание структуры; не дублируйте один и тот же код в нескольких каталогах ради шаблона.
