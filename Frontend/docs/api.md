# Описание API (Java backend)

Базовый адрес Java backend: `http://localhost:8080`.
Из frontend все запросы идут через прокси Vite по относительным адресам
(`/api/...`), префикс `/api` сохраняется.

## Используемые методы

| Метод  | Адрес               | Назначение                          |
| ------ | ------------------- | ----------------------------------- |
| GET    | `/api/products`     | Получить каталог изделий            |
| GET    | `/api/orders`       | Получить список заказов             |
| POST   | `/api/orders`       | Создать заказ                       |
| DELETE | `/api/orders/{id}`  | Отменить заказ (переводит в `CANCELLED`) |

## Создание заказа

`POST /api/orders`

Тело запроса:

```json
{
  "dueDate": "2026-11-15",
  "comment": "Тестовый заказ",
  "items": [
    { "productId": 1, "quantity": 10 },
    { "productId": 2, "quantity": 5 }
  ]
}
```

| Поле          | Тип      | Правила                                |
| ------------- | -------- | -------------------------------------- |
| `dueDate`     | string   | `YYYY-MM-DD`, обязательное, не в прошлом (`@FutureOrPresent`) |
| `comment`     | string   | необязательное, до 200 символов        |
| `items`       | array    | обязательное, непустое                 |
| `items[].productId` | number | обязательное, положительное        |
| `items[].quantity`  | number | обязательное, положительное        |

Не передаются (формирует сервер): `id` заказа, `id` позиции, название
изделия, `status`, `priority`, `createdAt`.

### Объединение одинаковых изделий

Сервер объединяет позиции с одинаковым `productId` и суммирует количество.
Например, две позиции `{ productId: 1, quantity: 10 }` и
`{ productId: 1, quantity: 5 }` дают одну позицию `{ productId: 1, quantity: 15 }`.

## Структуры ответов

### Изделие (`GET /api/products` → массив)

```json
[
  { "id": 1, "title": "Вал приводной", "description": "Деталь для передачи крутящего момента" }
]
```

Поле `description` может быть `null`.

### Заказ (`GET /api/orders`, `POST /api/orders`, `DELETE /api/orders/{id}`)

```json
{
  "id": 3,
  "dueDate": "2026-11-15",
  "priority": "MEDIUM",
  "status": "NEW",
  "createdAt": "2026-11-13T12:00:00",
  "comment": "Тестовый заказ",
  "items": [
    { "id": 7, "productId": 1, "productTitle": "Вал приводной", "quantity": 10 }
  ]
}
```

Значения `priority`: `HIGH`, `MEDIUM`, `LOW`.
Значения `status`: `NEW`, `READY_FOR_PLANNING`, `PLAN_PROPOSED`, `PLANNED`,
`IN_PRODUCTION`, `COMPLETED`, `CANCELLED`.

## Фактические HTTP-статусы

| Метод  | Успех | Описание                                    |
| ------ | ----- | ------------------------------------------- |
| GET    | 200   | каталог / список заказов                    |
| POST   | **200** | создан (не 201)                          |
| DELETE | **200** | заказ со статусом `CANCELLED` (тело есть) |
| —      | 404   | заказ/изделие не найдено                    |
| —      | 400   | ошибка валидации (например, дата в прошлом, пустые позиции) |

Успех проверяется через `response.ok`, а не по конкретному коду.

## Отмена заказа

`DELETE /api/orders/{id}` **не удаляет** запись, а переводит её в статус
`CANCELLED` и возвращает обновлённый заказ. Строку в списке нужно заменять
объектом из ответа, а не удалять. Повторная отмена уже отменённого заказа
возвращает его без изменений.

## Примеры ошибок

Ошибка 404 (несуществующий заказ):

```json
{
  "status": 404,
  "error": "Not Found",
  "message": "Заказ с ID = 999 не найден"
}
```

Ошибка 404 (несуществующее изделие):

```json
{
  "status": 404,
  "error": "Not Found",
  "message": "Деталь с ID = 999 не найдена!"
}
```

Если в теле ответа есть непустое поле `message`, оно показывается
пользователю. Для ответов другого формата (включая не-JSON) показывается
общее сообщение вида «Не удалось выполнить запрос. Код ответа: 500».

Два разных случая «сервер недоступен»:

- **Остановлен Java backend** (Vite при этом работает): прокси Vite возвращает
  `502 Bad Gateway`, клиент показывает «Не удалось выполнить запрос.
  Код ответа: 502».
- **Недоступен сам Vite / сеть**: `fetch` не может выполниться, клиент
  показывает «Не удалось связаться с сервером. Проверьте, запущен ли
  Java backend.»
