# Frontend (React + Vite)

Интерфейс «Мастер-план»: каталог изделий, форма заказа и список заказов.
Подключается к Java backend через прокси Vite.

## Запуск

```bash
cd Frontend
npm install
npm run dev
```

Приложение открывается на `http://localhost:5173`.

Перед работой в режиме `api` нужно запустить Java backend
(см. `JavaBackend/production-java-backend`):

```bash
cd JavaBackend/production-java-backend
./mvnw spring-boot:run
```

> ⚠️ **Порт Java в этом проекте — 8080** (`application.properties`:
> `server.port=8080`; Go backend занимает 8081). В некоторых формулировках
> задания указан порт 8081 — это не соответствует устройству проекта.

## Параметры окружения (`.env`)

Создайте файл `Frontend/.env` по образцу `.env.example`:

| Переменная          | Назначение                                           | Значения                  |
| ------------------- | ---------------------------------------------------- | ------------------------- |
| `VITE_DATA_MODE`    | Режим данных                                         | `mock` (по умолч.) / `api` |
| `JAVA_API_TARGET`   | Адрес Java backend для прокси `/api`                 | `http://localhost:8080`   |

- `mock` — демонстрационный режим: данные из `src/mocks/mockData.js`,
  HTTP-запросы не выполняются, сохранение недоступно.
- `api` — данные загружаются из Java backend, создание и отмена заказов
  выполняются через HTTP-клиент.

Клиентские функции используют только относительные адреса (`/api/products`,
`/api/orders`). Прокси настроен в `vite.config.js`: запросы `/api`
перенаправляются на `JAVA_API_TARGET`, префикс `/api` сохраняется.

> После изменения `.env` (или `.env.example`) **перезапустите Vite** —
> переменные окружения читаются только при старте.

## Режим работы

Режим выбирается централизованно в `src/config/dataMode.js`
(значение по умолчанию — `mock`).

Переключение в режим API:

```bash
# вариант 1: через .env
echo "VITE_DATA_MODE=api" > .env
echo "JAVA_API_TARGET=http://localhost:8080" >> .env

# вариант 2: инлайн при запуске
VITE_DATA_MODE=api npm run dev
```

## Проверка интеграции

1. Запустить Java backend на 8080.
2. Включить `VITE_DATA_MODE=api` и перезапустить Vite.
3. Открыть «Каталог» — изделия загружаются из Java (`GET /api/products`).
4. Перейти «к оформлению», выбрать два изделия, заполнить дату и комментарий.
5. Отправить заказ — появляется сообщение «Заказ № … создан», заказ в списке.
6. Обновить страницу — заказ остаётся в списке.
7. Нажать «Отменить» — статус меняется на `CANCELLED`, кнопка отключается.
8. Обновить страницу ещё раз — статус `CANCELLED` сохраняется.

Проверка ошибок:

- остановить Java → интерфейс показывает ошибку запроса (прокси Vite вернёт `502`);
- неуспешный `POST` → введённые значения сохраняются;
- отмена несуществующего заказа → ошибка 404;
- повторное нажатие во время отправки → второй запрос не создаётся;
- режим `mock` → нет HTTP-запросов и фиктивного сохранения.

## Структура

```
src/
  api/                 HTTP-клиент и функции обращения к API
    httpClient.js      requestJson()
    productsApi.js     getProducts()
    ordersApi.js       getOrders(), createOrder(), cancelOrder()
  components/orders/
    OrderForm.jsx      форма заказа
  config/
    dataMode.js        выбор режима mock / api
  mocks/
    mockData.js        демонстрационные данные
  pages/
    ProductsPage.jsx   каталог
    CreateOrderPage.jsx создание заказа
    OrdersPage.jsx     список и отмена заказов
```

> **Примечание об `OrderForm`.** По исходному заданию компонент
> `OrderForm` — это готовая зависимость из задания №2. В репозитории он
> отсутствовал (проверено по всем веткам), поэтому в рамках этой задачи
> создана базовая рабочая версия `src/components/orders/OrderForm.jsx`:
> выбор изделий, добавление/удаление позиций, изменение количества,
> объединение повторно выбранного изделия, валидация даты/количества/
> комментария и вызов `onSubmit(payload)`.

Подробное описание API — в [docs/api.md](docs/api.md).
